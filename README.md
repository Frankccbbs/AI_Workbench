# Tobacco800 签名检测与模型评估可视化工作台

本项目是一个轻量、高效的 Web 应用，专为 **Tobacco800 数据集** 的手写签名检测任务设计。它不仅提供了 Ground Truth (GT) 标注的可视化，更核心的功能在于它是一个**多模态大模型（Vision LLMs）评测工作台**。

通过简单的 UI 交互，你可以直接调用 GPT-4o、Claude-3、Qwen 等模型对文档扫描件进行目标检测，并实时获得框级别的准确率（命中、漏检、误报、位偏）统计反馈。

---

## 一、 系统特性 (Features)

1. **画布级可视化**：支持无极缩放、拖拽。可一键叠加显示 GT 签名框（绿色）、GT Logo 框（蓝色）与 AI 推理框（紫色）。
2. **LLM 实时推理**：通过兼容 OpenAI /v1 接口的 API 代理，快速接入各种视觉大语言模型，并支持动态调整送入模型的图像分辨率（缩放比例）。
3. **“贪心”匹配算法与指标统计**：
   - 自动计算 AI 预测框与 GT 框的 IoU（交并比）与覆盖率。
   - 通过动态滑块调节「覆盖率阈值（默认 50%）」，实时得出 TP（正确命中）、TN、FP（误报）、FN（漏检）及“位置偏离”等严格指标。
4. **增量/强制批量跑库**：支持一键对整页文档进行并发检测。智能跳过已检测文件以节省 Token 成本，亦可强制重跑。
5. **数据防丢快照**：内置静默备份机制。在修改 JSON 文件前，系统会自动在后台备份（5分钟防抖），确保宝贵的实验数据在模型调参时不会意外丢失。

## 二、 安装与启动指南 (Installation)

### 1. 环境依赖
本项目后端极简，仅需少量基础库：
```bash
pip install Flask Pillow requests
```
*(要求 Python 3.8+)*

### 2. 目录与数据准备
请严格确保本项目根目录下存放了完整的 Tobacco800 数据集，结构如下：
```text
signature_test/
├── app.py                 # Flask 后端主程序
├── ai_results.json        # AI 推理结果持久化文件
├── ai_results_history/    # 自动生成的备份快照目录
├── static/                # 前端静态资源 (JS/CSS)
├── templates/             # 视图模板 (index.html)
└── datasets/              # 核心数据集 (必须手动放好)
    ├── Tobacco800_SinglePage/Tobacco800_SinglePage/SinglePageTIF/
    │   └── *.tif          # 所有高清原图
    └── Tobacc800_Groundtruth_v2.0/Tobacc800_Groundtruth_v2.0/XMLGroundtruth_v2.0/
        └── *.xml          # Ground Truth 标注坐标
```

### 3. 运行服务
在终端中进入项目根目录，直接运行：
```bash
python3 app.py
```
终端提示 `Running on http://127.0.0.1:5001` 后，在浏览器中打开该地址即可。

## 三、 使用说明 (User Guide)

### 1. 系统设置 (Settings)
首次启动后，点击右上角的 **⚙ 设置** 按钮，必须填写以下两项：
- **API 代理地址**：如 `https://api.yunwu.ai/v1`
- **API Key**：你的 Bearer 令牌

**检测 Prompt (重点)**：
默认 Prompt 已内置了极其严格的 **Tight Bounding Box (紧密边界框)** 指令。多模态模型常有“空间幻觉”（凭借经验猜坐标而非真实看图），**请勿删减默认 Prompt 中强调 Exact wrap 边界的约束要求**。

### 2. 左侧过滤面板 (Filters)
- **全部**：显示当前分页下全部 30 个文件。
- **有签名**：仅筛选 GT 标注中含有签名的文件。
- **已检测**：仅筛选已经用大模型跑过结果的文件。
- **✅ 命中 / ❌ 漏检 / ⚠️ 位偏**：这三个标签**完全基于右侧详细面板的数据**，依赖于当前设定的“覆盖率阈值”。用于快速筛查大模型表现不佳的异常 Case。

### 3. 批量与增量检测
点击顶部的「批量检测」：
- **仅检测未跑过的**：跳过已存在于 `ai_results.json` 中的文件（省钱模式）。
- **强制重新跑全部**：忽略历史记录，用最新的模型和缩放比例把当前页全刷一遍。*(触发此操作时，系统会自动在 `ai_results_history` 创建备份)*

## 四、 设计文档与技术架构

### 前后端分工
本系统采用轻量化设计，没有复杂的构建工具（Webpack/Vite）和现代框架（React/Vue），而是纯靠原生 DOM 实现，以确保最低的维护门槛。

* **后端 (`app.py`)**：
  承担网关与数据持久化作用。将体积巨大的 `.tif` 转码缩放为 `.png`，以及将 Base64 编码的图像外包发送给 LLM 接口。包含基于 `shutil` 的 JSON 数据备份模块。
* **前端 (`static/app.js`)**：
  核心大脑。不仅负责通过 `canvas` 绘制多层 Bounding Box，还负责执行一套 **“贪心匹配算法” (Greedy Match)**：将 AI 生成的候选框与 GT 真实框进行一对多的交叉对比覆盖率计算，以此判定单文件的真实召回率。

### 命中逻辑判定（重要）
系统是 **File-Level (文件级)** 宽容评价的：
1. 若 GT 中存在签名，且 AI 返回了多个框，只要 **其中一个框** 对 GT 的覆盖率大于阈值（默认 50%），该文件即视为 **✅ 命中 (TP)**。
2. 虽然 AI 可能多画了错误的位置（误报框 FP），但只要真签名被找出来了，当前在 UI 的徽章上不会把该文件打上失败烙印。

## 五、 二次开发注意事项

1. **缓存坑**：如果你修改了 `index.html` 的结构，必须**重启 Flask 服务器**，因为 Flask 在非 Debug 模式下会强缓存模板。如果你修改了 `app.js` 或 `style.css`，在浏览器使用 `Cmd+Shift+R` 强制硬刷新即可。
2. **多模态模型选型建议**：
   - 当前测试表明，`gpt-4o` 在高分辨率文档中空间定位能力较强，而早期的模型（如 `gpt-5.2`）即便改了 prompt 依然会在纯白区域凭空产生“签名幻觉”。
   - 若成本允许，建议在设置中保持较高的图像比例 (`0.5 - 0.75`) 运行测试，以防止签名被压缩成墨团导致模型失明。
3. **扩展指标**：如果未来你需要将系统从“文件级判定”升级为更加严格的“框级判定”（例如：不仅要找准，而且不能多找任何误报框），你需要重写 `app.js` 中的 `computeFileLabel` 函数，新增类似于 `strict-TP` 的状态，并更新对应的 CSS 颜色体系。
